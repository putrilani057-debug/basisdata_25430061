2. Ringkasan Dasar TeoriDBMS (Database Management System) adalah perangkat lunak yang berfungsi mengelola penyimpanan, keamanan, dan pengaksesan data terstruktur. MariaDB berarsitektur client-server, di mana proses server (mysqld) berjalan secara independen mendengarkan permintaan pada port TCP 3306. Klien (seperti CLI atau phpMyAdmin) mengirimkan perintah SQL, kemudian server memproses dan mengembalikan hasilnya.   XAMPP digunakan sebagai lingkungan pengujian lokal yang mengintegrasikan Apache, MariaDB, PHP, dan phpMyAdmin. Menguasai klien CLI sangat penting karena perintah berbasis skrip bersifat reproducible, dapat disimpan ke kendali versi Git, dan menjadi standar di lingkungan produksi. Pengelolaan akses basis data wajib menerapkan prinsip least privilege, di mana akun kerja harian diberi hak terbatas hanya pada objek basis data yang relevan.

4. Jawaban Titik AnalisisTitik Analisis
1:Pertanyaan: Label tombol bertuliskan "MySQL", tetapi yang berjalan adalah MariaDB. Apa konsekuensinya ketika mencari solusi galat di internet? Kapan dokumentasi MySQL masih relevan, dan kapan harus merujuk ke MariaDB?   Jawaban: MariaDB merupakan fork dari MySQL, sehingga fungsi dasar SQL (seperti DDL, DML, sintaks SELECT, JOIN, dan indeks standar) sebagian besar kompatibel dan dokumentasi MySQL masih sangat relevan. Namun, dokumentasi MariaDB wajib dirujuk ketika berhadapan dengan fitur spesifik MariaDB (seperti mesin penyimpanan Aria/Connect, sintaks ekstensi tertentu, fungsi JSON khusus, atau perilaku pesan kesalahan spesifik versi).

Titik Analisis 2:Pertanyaan: Ketika mencoba masuk dengan mysql -u root tanpa -p, bagian mana dari pesan galat yang memberi tahu bahwa klien tidak mengirim password?   Jawaban: Pesan kesalahan yang muncul adalah ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO). Bagian (using password: NO) secara eksplisit menandakan bahwa klien mencoba melakukan autentikasi tanpa mengirimkan parameter kata sandi.

Titik Analisis 3:Pertanyaan: Mengapa information_schema tetap terlihat oleh mhs_123, sedangkan mysql ditolak dengan ERROR 1044? Apa bedanya kode galat 1044 dengan 1045?   Jawaban: information_schema adalah basis data standar ANSI/ISO SQL yang berisi metadata Read-Only tentang seluruh struktur objek yang diizinkan untuk dilihat oleh pengguna. Sebaliknya, basis data mysql berisi tabel internal sistem dan kredensial autentikasi global server, sehingga dibatasi ketat.   Perbedaan Kode Galat:ERROR 1045 (Access Denied / Autentikasi): Terjadi di tingkat koneksi/masuk (gagal melakukan verifikasi pengguna atau kata sandi).   ERROR 1044 (Access Denied / Otorisasi): Pengguna berhasil masuk (autentikasi sukses), tetapi ditolak saat mencoba mengakses atau melakukan operasi pada basis data yang tidak berada di dalam cakupan hak aksesnya (GRANT).

Titik Analisis 4:Pertanyaan: Mode cookie meminta pengguna mengetik password setiap kali masuk. Mengapa mode ini lebih aman daripada mode config?   Jawaban: Mode config menyimpan kata sandi pengguna secara plain-text di dalam berkas skrip config.inc.php di server web, yang berisiko tinggi terbaca jika terdapat celah keamanan atau salah konfigurasi hak akses berkas. Mode cookie mengamankan kredensial dengan mengharuskan autentikasi aktif interaktif dan menyimpannya secara terenkripsi dalam sesi peramban terbatas, sesuai dengan standar keamanan web.
